# 事件总线系统升级说明

本文档详细说明Neo4j编辑器前端代码库中事件管理系统的升级情况，从原来的eventManager升级为全新的eventBus系统。

## 升级概述

我们对Neo4j编辑器的事件系统进行了全面升级，主要包含以下变更：

1. 创建了全新的`eventBus`模块，替代原来的`eventManager`模块
2. 重构了核心模块之间的通信机制
3. 优化了事件命名规范，采用更简洁的格式
4. 增强了事件系统的功能，添加了节流、防抖和命名空间支持
5. 重新组织了模块初始化顺序，确保依赖关系正确

## 新的模块架构

升级后的核心模块包括：

1. **eventBus** - 事件总线，负责所有模块间的通信
2. **configManager** - 配置管理器，负责应用配置的管理
3. **userManager** - 用户管理器，负责用户认证和权限管理
4. **dataManager** - 数据管理器，负责与Neo4j数据库的交互
5. **graphManager** - 图表管理器，负责管理树视图和网络图视图
6. **applicationManager** - 应用管理器，负责协调所有模块

## 事件命名规范

新的事件系统采用更简洁的命名格式：

- 旧格式：`moduleName:eventName` (例如：`configManager:update`)
- 新格式：`domain:eventName` (例如：`config:update`)

主要域名空间包括：
- `app` - 应用程序级事件
- `user` - 用户相关事件
- `config` - 配置相关事件
- `data` - 数据相关事件
- `graph` - 图表相关事件
- `ui` - 用户界面相关事件

## 已更新的文件

1. **创建的新文件**：
   - `js/core/eventBus.js` - 新的事件总线模块
   - `js/core/dataManager.js` - 数据管理器模块
   - `js/core/graphManager.js` - 图表管理器模块
   - `test-eventbus-integration.html` - 集成测试文件

2. **更新的文件**：
   - `js/main.js` - 更新了模块加载顺序

   - `index.html` - 优化了HTML结构和样式引用

## 事件总线API使用指南

### 基本用法

```javascript
// 获取事件总线实例
const eventBus = neo4jEditor.getModule('eventBus');

// 订阅事件
eventBus.on('user:login', function(event, data) {
    console.log('用户登录:', data.username);
});

// 发布事件
eventBus.emit('user:login', { username: 'admin', password: 'password' });

// 取消订阅
eventBus.off('user:login');

// 订阅一次事件（只触发一次）
eventBus.once('config:changed', function(event, data) {
    console.log('配置已更改:', data);
});
```

### 命名空间

```javascript
// 使用命名空间订阅
eventBus.on('user.*', function(event, data) {
    console.log(`用户相关事件: ${event.name}`, data);
});

// 使用命名空间取消订阅
eventBus.off('user.*');
```

### 节流和防抖

```javascript
// 使用节流（500ms内最多触发一次）
eventBus.on('ui:resize', function(event, data) {
    console.log('窗口大小调整:', data);
}, { throttle: 500 });

// 使用防抖（500ms后没有新事件才触发）
eventBus.on('ui:input', function(event, data) {
    console.log('用户输入:', data.value);
}, { debounce: 500 });
```

## 预定义事件列表

### 应用程序事件
- `app:initialized` - 应用初始化完成
- `app:started` - 应用启动
- `app:paused` - 应用暂停
- `app:resumed` - 应用恢复
- `app:shutdown` - 应用关闭
- `app:error` - 应用错误

### 用户事件
- `user:login` - 用户登录
- `user:logout` - 用户登出
- `user:loginSuccess` - 登录成功
- `user:loginError` - 登录失败
- `user:preferencesUpdated` - 用户偏好更新

### 配置事件
- `config:update` - 配置更新
- `config:reset` - 配置重置
- `config:themeChanged` - 主题更改

### 数据事件
- `data:connected` - 数据库连接成功
- `data:disconnected` - 数据库连接断开
- `data:queryStart` - 查询开始
- `data:queryComplete` - 查询完成
- `data:queryError` - 查询错误
- `data:nodeCreated` - 节点创建
- `data:nodeDeleted` - 节点删除
- `data:relationshipCreated` - 关系创建
- `data:relationshipDeleted` - 关系删除

### 图表事件
- `graph:loaded` - 图表数据加载完成
- `graph:nodeSelected` - 节点被选中
- `graph:relationshipSelected` - 关系被选中
- `graph:layoutApplied` - 布局应用完成
- `graph:viewChanged` - 视图切换

## 注意事项

1. 确保所有模块都按照新的事件命名规范更新了事件监听器和触发器
2. 在开发新功能时，请使用新的事件总线系统而不是旧的eventManager
3. 如果遇到事件未触发或未接收的问题，请检查事件名称是否正确
4. 对于频繁触发的事件，建议使用节流或防抖功能来提高性能

## 故障排除

### 常见问题及解决方案

1. **模块未加载**
   - 检查模块名称是否正确
   - 确保模块在`main.js`的`coreModules`数组中
   - 验证模块的依赖关系是否正确

2. **事件未触发**
   - 检查事件名称是否使用了新的命名格式
   - 确认事件总线实例是否正确获取
   - 验证发布事件的代码是否被执行

3. **事件未接收**
   - 检查订阅事件的代码是否在事件发布之前执行
   - 确认事件名称是否完全匹配
   - 验证事件处理函数是否正确绑定

4. **性能问题**
   - 对于高频事件，使用节流或防抖
   - 及时取消不再需要的事件订阅
   - 避免在事件处理函数中执行耗时操作

如有其他问题，请查看浏览器控制台的错误信息，或参考源代码中的详细注释。
