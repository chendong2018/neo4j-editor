# Neo4j编辑器双视图功能开发计划

## 需求分析

根据需求，我们需要实现一个双视图系统，其中每个节点同时具有两种关系，第一种是父子关系，第二种是依赖关系，为了方便理解，因此需要将节点同时存并显示在两种结构中：
1. **层级树**：显示完整的所有节点父子关系（CHILD_OF关系），这里的层级树指的是节点的父子关系以树形的方式存储，需确保完整展示所有节点的层级关系链。
2. **同父节点关系网**：显示当前节点的所有同父节点，以及与他们的RELATES_TO关系，这里的同父节点级指的是层级树中的一个挂在同一个父节点下的所有节点（如果不具有同父关系则不认为是同层级），同层级节点之间的互相联系以网形方式存储。

核心目标：
- 节点添加时自动维护两种关系
- 可手动和批量维护节点属性
- 任一视图中的操作都应同步到另一视图
- 自动维护同父节点关系网关系（同一个父节点下的节点之间的双向连接）
- 这些关系应正确保存到Neo4j并从Neo4j加载
- 可配置在neo中存储的标签
- 支持标签过滤功能，可选择显示或隐藏特定标签的节点
- 每个节点必须拥有唯一的code字段，系统需提供code检查机制确保无重复
- 可通过code字段进行节点查询（精确查询和模糊查询）
- 完善节点关系管理机制，特别是父子关系通过关系而非属性表示
- 节点实体只存储一次，但通过不同关系连接到其他节点，在界面上分别在树视图和网视图中显示
- 支持自主添加节点属性，也可批量添加节点属性
- 允许自定义节点（包括标签、属性等），方便用户操作
- 连接到Neo4j后，用户选择保存时能将数据正确存储，确保每个节点在Neo4j中只有一个对应实体
- 连接到Neo4j后，能够自动显示符合特定标签的节点，并将其正确显示在树视图和网视图中

## 技术实现方案

### 1. 数据模型设计

**节点属性扩展：**
- 不通过`parent_id`属性，通过CHILD_OF关系表示层级结构
- 节点确保在两个视图中都显示，同一节点通过在两个视图中展示不同关系，实现双视图同步
- 添加可配置的Neo4j标签系统
- 为每个节点添加`code`属性，确保节点的唯一性
- 支持自主添加和批量管理节点属性
- 支持节点模板配置，允许自定义节点（标签、属性等）

**关系类型定义：**
- `CHILD_OF`：表示节点之间的父子层级关系
- `RELATES_TO`：表示同一父节点下节点之间的双向依赖关系
- 允许用户添加其他自定义关系

### 2. 核心功能开发

#### 2.1 双视图初始化与同步机制

修改`initializeDualViews`函数，确保两个视图正确初始化并共享数据：
- 统一使用`window.sharedGraphData`作为数据源
- 确保树视图显示完整的所有节点父子关系，使用树形布局算法清晰展示层级关系链
- 同父节点关系网显示当前节点的所有同父节点，以及与他们的关系，使用优化布局展示这些关系
- 监听节点和关系的删除/修改事件，确保两个视图数据一致
- 实现标签过滤功能，支持按标签筛选节点显示

#### 2.2 节点添加功能改造

增强节点添加逻辑，实现以下功能：
- 新增节点同时添加到`window.sharedGraphData`
- 通过CHILD_OF关系而非节点属性表示层级关系
- 为新节点生成唯一的code属性
- 添加节点时验证code的唯一性
- 根据节点所在层级，自动创建或更新同级网关系
- 调用`syncGraphData`确保两个视图同步更新
- 支持通过节点模板快速创建自定义节点
- 支持批量添加节点属性

#### 2.3 同父节点关系网自动维护

实现一个自动维护同父节点关系的模块：
- 当节点父节点变更时，自动更新其在关系网中的连接
- 确保同一父节点下的所有节点之间都有双向的RELATES_TO关系
- 避免创建重复关系
- 当节点添加到某个父节点下时，自动与该父节点的所有其他子节点建立关系
- 记录用户手动删除的关系，确保这些关系不会被自动重新创建

#### 2.4 层级树关系管理

开发层级关系管理功能：
- 提供设置节点父节点的功能
- 当父节点变更时，自动更新关系网络
- 维护正确的父子关系链
- 防止循环引用的检查机制

### 3. 数据持久化

#### 3.1 数据导出到Neo4j

修改数据导出功能，确保：
- 节点数据包含code属性，确保唯一性
- 通过CHILD_OF关系表示层级结构，不再使用节点属性
- 确保节点只保存一次，通过关系连接不同节点
- 正确保存CHILD_OF和RELATES_TO两种关系，使它们能在其他地方用于查询
- 确保关系的双向性正确记录
- 根据配置应用适当的Neo4j标签
- 提供用户手动触发保存的功能，连接到Neo4j后在用户选择保存时执行数据存储
- 实现code唯一性验证，确保Neo4j中每个节点只有一个对应的实体
- 允许用户通过export按钮将数据导出为neo语句

#### 3.2 数据从Neo4j加载

增强数据加载功能，实现：
- 通过CHILD_OF关系重建层级结构，不依赖节点属性
- 识别并加载CHILD_OF和RELATES_TO关系
- 加载后自动重构层级树和同父节点关系网
- 正确处理配置的Neo4j标签
- 确保节点code的唯一性
- 连接到Neo4j后，根据用户选择的标签自动过滤和加载节点
- 加载的节点能够在树视图和网视图中正确显示其层级关系和同级关系

### 4. UI/UX优化

#### 4.1 双视图界面优化

改进现有分割视图布局：
- 确保两个视图有清晰的视觉区分
- 添加明确的父节点关系指示
- 提供父节点调整的便捷操作
- 显示节点所属父节点的信息

#### 4.2 属性配置界面

开发节点和标签配置界面：
- 提供Neo4j标签配置功能
- 允许配置节点的code属性，并提供唯一性验证
- 允许通过CHILD_OF关系设置节点的父节点
- 支持批量操作节点属性
- 提供标签过滤功能，支持多标签组合过滤
- 提供节点属性自主添加和编辑界面
- 实现节点模板保存和应用功能

#### 4.2 操作反馈机制

增强用户交互反馈：
- 提供清晰的操作状态提示
- 添加节点层级变化的视觉反馈
- 实现同级关系创建的动画效果

## 风险与应对

1. **性能风险**：同一父节点下节点过多时，RELATES_TO关系数量可能爆炸式增长；标签过滤操作可能影响性能
   - 应对：实现智能关系管理，只显示可视区域内的关系；提供关系过滤选项；优化标签过滤算法

2. **数据一致性风险**：双视图可能出现数据不一致
   - 应对：统一数据源，严格控制数据更新流程；实现事务式的数据更新机制

3. **循环引用风险**：父子关系可能形成循环
   - 应对：实现严格的循环引用检测机制，阻止可能导致循环的操作

4. **用户体验风险**：复杂的关系可能导致视图混乱
   - 应对：提供视图过滤和焦点功能，增强可视化效果；实现关系密度控制

5. **配置复杂性风险**：Neo4j标签配置可能增加系统复杂度
   - 应对：提供直观的配置界面；添加合理的默认配置；提供配置验证
